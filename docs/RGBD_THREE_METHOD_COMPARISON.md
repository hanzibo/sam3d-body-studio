# RGB-D：逐帧网络、独立 CUDA60 与两种连续细化对照

## 复现实验

使用已准备的 `outputs/depth-fusion/tracking-v1/{arms,cross,turn,recover}`，每组相同 200 帧，约 10 Hz 输入采样。不是 10 Hz 在线性能声明。

```bash
/run/media/hzb/Data/conda-envs/sam3d-body/bin/python -m studio.rgbd.rgbd_comparison
```

控制器使用当前配置的 Fast 与 Standard Conda 环境，推理在一个 GPU 独占 worker 内顺序运行；SAM3 不常驻。可用 `--stage infer` / `--stage evaluate` 分开执行。每个结果帧和网络缓存有内容哈希；只有清单、输入、标定、配置和源码匹配时才续跑。改变实验代码或输入需选新的 `--output`，不得覆盖历史结果。

## 三方案定义

1. **逐帧独立网络**：Fast384 身体模式，同一检测框、彩色内参，不读 SAM3 掩膜。不做深度修正，不额外对齐。
2. **独立网络＋CUDA60**：同一网络结果，复用既有完整基线：平移深度校正 → 刚体 60 步 → 身体姿态 60 步。保留官方参数边界、guard 接受检查、分数回退。使用本轮冻结的离线 SAM3 掩膜；不是只运行 60 次操作，也不与无掩膜方案等价输入。体型每帧来自网络，不优化体型/尺度。
3. **初始化＋连续少步细化**：直接恢复原 `candidate-15/states` 的已保存结果，而非重跑择优。首帧、每秒和失败恢复运行网络＋60 步，普通帧以前帧为初值做 15 步。固定段内体型、表情和手部，不读 SAM3 掩膜选点。LOST 不显示旧人体，DEGRADED 不冒充有效结果。

均使用 Fast384、原骨干 TRT / 检测 TRT / 解码器、MHR 和中间预测编译配置。对比不能解耦体型固定、拟合目标和掩膜贡献，后续消融需单独控制这些变量。

4. **仅首帧初始化＋连续少步细化**：同样的无掩膜首帧网络预测＋60 步初始化，后续全部 15 步；关闭每秒、质量失败和出画返回时的网络重新初始化。检测框、YOLO 关键点和原始深度仍随帧更新。出画不显示旧人体，但内部保留最后一次接受的姿态；返回后只能从该状态尝试恢复，失败明确标记，不自动调用 SAM 修复。全片体型、表情保持首帧值。

新增第四列可独立复现，不重跑或覆盖已完成的前三列：

```bash
/run/media/hzb/Data/conda-envs/sam3d-body/bin/python -m studio.rgbd.rgbd_first_init
```

默认输出 `outputs/depth-fusion/tracking-comparison-four-v1/`。前三列的网格、关节、指标和计时逐项原样复用，并校验内容哈希；只运行新增的首帧初始化消融。视频前三列复用原始已导出帧后重新编码，第四列采用相同观察相机和参考测量。每组 200 帧；四列视频为 2560×840，播放速度仍是源时间。

`first_init_run/first-init-15/` 保存其状态、实际对应点和计时，只有第 0 帧允许 `keyframe=true`，其后网络耗时必须为 0。模型仍需在实验开始时加载和预热；这不是启动时间为 0。逐帧网格的归档计算不计入推理核心时间，也不计入该方案的输入处理时间估计。

## 误差与时间口径

- 标定原始深度的所有有效测量点到去畸变彩色相机系；全分辨率最近 Z 投影，不填洞，不用优化器对应筛选代替评估。
- 深度 MAE / P90：人体掩膜、有效测量与模型可见面的交集。另报告完整轮廓 IoU、人体区域覆盖率和缺失模型按 100 mm 计的截断误差，防止小交集得到虚假的好分数。
- 点到三角面：每帧最多 256 个均匀测量点，固定随机种子；三种方案共用同一组点，不按拟合残差删点。计算到完整三角面的精确最近距离；不评价不可见背面。该采样数与旧静态 2000 点不同，不能直接混为同一指标样本。
- 质量主表按三种方案共同有效且有参考分割的帧等权平均，同时报告各方案有效数量和完整逐帧 CSV。不把 LOST 丢失隐藏在误差均值中。
- 四列报告改用四种方案的共同有效帧；另列各自全部有效帧的深度/点面 MAE，不能因为第四方案失效、只剩容易帧就宣称原方案误差下降。JSON 另给 0–5、5–10、10–15、15–20 秒分窗误差和有效帧数，用于查看误差随时间的变化与覆盖情况；同时存在动作难度变化，不能把分窗误差变化全部归因于漂移。
- 原始和人工修订 SAM3 都只是图像参考，不是人体关节真值。参考漏分会偏置结果。高置信关键点未被覆盖的帧标记待核查，完整统计仍保留，另报筛查后 MAE。
- 额外输出相对 CUDA60 的身体关键点差异、去根位置后的关键点差异、每帧左右肘角。这是方案一致性，不是 MPJPE 真值误差。YOLO 重投影已用于跟踪目标，只是诊断。
- 预设静止区间为 0.25–1.75 s，位置和肘角去线性趋势后统计。区间仍可能有自然人体晃动；不代表运动段抖动或动作延迟。
- 核心成本包含检测、网络与所需的后处理/接受检查。解码和全深度构建另外记录，另给输入成本估计。网络缓存保留原同步测量时间，不记作零。跟踪时间来自上一轮记录，比较批次不同。
- 新基线的模型进程启动和图捕获单独记录；导出、精确评估、视频生成和显示不并入核心时间。历史跟踪首帧的阶段时间包含其当时图构建，原始记录保留，首帧需单独解释；缓存的历史网络首帧也可能含首次形状开销。主表包含关键帧及首帧，不可称为纯热帧统计。表格不是完整在线吞吐证明。评估和视频生成应在推理结束后运行，避免干扰 GPU 计时。

## 连续视频与交互式三维查看

默认输出 `outputs/depth-fusion/tracking-comparison-v1/`：

- `report.html`：四组合览、三方案量化表和各组视频。
- `playlist.mp4`：四组按序连续播放，约 80 秒。
- `各组/report/comparison.mp4`：三列同步，上排 RGB 网格叠加，下排固定斜视角人体参考点云叠加。各列相机完全一致，不对人体额外刚性或尺度对齐。视频播放速度是源时间，不是处理帧率。
- `各组/report/frames.csv`、`rows.json`、`summary.json`：逐帧状态、指标、肘角、成本和定义。
- `各组/frames/*.npz`：三方案相机系完整网格、127 关节、70 关键点、有效标记。`topology.npz` 单独保存拓扑。
- `各组/report/replay/*.npz`：仅用于显示的真实点云子样本、RGB 和参考人体标记；完整测量用于评估，显示采样不参与拟合。
- `各组/reference/`：本轮冻结参考，后续手动改分割不会静默改变此轮结果。

重启 Studio → **RGB-D 跟踪对照** → 扫描已有对照。支持四组顺序循环、暂停逐帧、三场景视角联动、网格透明度、仅人体/完整场景点云，以及原 RGB 参考。磁盘读取在单个后台线程执行，队列有界；播放以源时间调度，设备较慢时跳过显示帧，暂停后可逐帧核查。此页不加载人体模型或 SAM3。

当前实验没有人工逐关节真值、同步外部动捕或独立动作轨迹标注，因此不会给出人体骨架绝对准确率、真实关节角误差或已通过动作延迟验收的结论。

## 本机实测结果（2026-11-07）

四段各 200 个约 10 Hz 采样帧，共 800 个时刻、3200 条方案结果。统一 Fast384 身体模式。以下单元格为 **深度 MAE / 点面 MAE，单位 mm**；按各组四方案共同有效帧等权平均。

| 场景 | 独立网络 | 独立＋CUDA60 | 周期初始化＋15步 | 仅首帧初始化＋15步 | 共同有效帧 |
|---|---:|---:|---:|---:|---:|
| 双臂抬放 | 103.40 / 90.52 | 17.57 / 15.49 | 20.67 / 16.88 | 22.30 / 18.02 | 200 |
| 交叉与屈肘 | 84.54 / 73.93 | 19.86 / 16.96 | 21.97 / 16.97 | 24.72 / 19.27 | 200 |
| 转身与移动 | 108.51 / 90.75 | 19.33 / 14.95 | 20.66 / 15.71 | 20.88 / 16.28 | 200 |
| 遮挡与恢复（参考待核查） | 119.95 / 99.07 | 24.92 / 20.22 | 24.81 / 17.49 | 25.11 / 17.91 | 141 |

以下为全部采样帧的核心成本 **中位数 / P95，单位 ms**，含第一帧和周期重置，LOST 帧只需检测而无人体拟合；可见帧口径另在 JSON/HTML 中列出。首帧图构建和模型启动不能按此表的中位数理解，历史与新增方案分批运行。

| 场景 | 独立网络 | 独立＋CUDA60 | 周期初始化＋15步 | 仅首帧初始化＋15步 |
|---|---:|---:|---:|---:|
| 双臂抬放 | 68.0 / 80.1 | 576.6 / 604.0 | 59.0 / 322.8 | 63.3 / 64.8 |
| 交叉与屈肘 | 68.4 / 79.1 | 579.8 / 614.1 | 58.0 / 340.2 | 63.5 / 64.9 |
| 转身与移动 | 68.8 / 79.1 | 581.3 / 899.4 | 57.8 / 348.6 | 63.3 / 64.7 |
| 遮挡与恢复 | 68.2 / 75.6 | 569.3 / 611.4 | 55.9 / 333.1 | 62.8 / 64.3 |

仅首帧初始化的输入处理成本估计中位数仍为约 121–123 ms（含解码、深度构建与缓存检测成本，不含 GUI/导出），因此尚未验收稳定在线 10 Hz。它减少了周期网络重置造成的尾延迟，普通帧计算量没有因此减少；不能把该批约 63 ms 的核心成本与另一批约 58 ms 的差异解释为初始化策略本身的开销差。

前三段四种方案各有 200/200 有效帧。遮挡组有 57 帧没有人体检测，独立网络/CUDA60 各 143/200 有效，周期初始化 141/200，仅首帧初始化 142/200。新方案的唯一 DEGRADED 帧为采样 154；出画时不显示旧人体，后续未触发网络重初始化。有效标记是算法接受检查的结果，并非真值准确率。

遮挡恢复组参考掩膜在采样 155、162–169 待人工核查，因此该组误差为暂定；全部帧均保留，JSON 另外列筛查后统计，未静默删除坏帧。现有短片中未观察到首帧方案持续单调增大的表面误差，但仅有约 20 秒且动作难度变化，不能据此保证长期无漂移或复杂遮挡下可恢复。

验证：7 项比较数据/指标/视频时间基测试通过；原三列与新增四列各完成 800 时刻的网格/坐标/哈希/状态/视频核验。新增结果的前三列与旧结果逐数组完全一致；每组只有第 0 帧为初始化帧，之后网络耗时为 0。实际 Qt 窗口完成四组播放、逐帧读取、精确保存网格、视角联动、隐藏网格和 LOST 无旧人体检查；未加载人体模型或 SAM3。另完成真实 EGL 共享渲染上下文及释放检查。

合辑使用滤镜统一各片段时间基，保留全部 800 帧；已校验总时长约 80 秒、时间戳严格递增且无超过 0.2 秒的拼接跳变。`playlist.json` 保存片段时长、帧数和内容哈希。禁止对具有不同时间基的这些 MP4 直接用 concat demuxer＋stream copy 合并。四列本轮评估器的原始源码另归档在结果根目录 `provenance/`，单组指标仍保留实际生成时的源码哈希。

首帧初始化采用同一程序重新执行，并非直接复制已有跟踪状态。实际两种连续方案首帧网格的最大顶点差：双臂/交叉/转身均小于 0.001 mm，遮挡组约 0.60 mm；后者不是严格逐位相同的初始状态，该组又有参考掩膜待核查，不能用其微小误差差异判断策略优劣。
