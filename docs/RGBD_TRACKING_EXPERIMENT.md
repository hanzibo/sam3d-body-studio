# RGB-D 时序细化与实际选点审计

本实现是离线 10 Hz 时间戳回放实验；不修改现有相机实时流，不宣称已经达到在线 10 Hz。人体参数、相机平移和每帧实际优化对应均保存，可独立用新的人工点提示 SAM3 参考重新检查落点。

## 如何查看与手动分割

重新打开 Studio，进入 **视频重建 → RGB-D 跟踪分割…**，选择已准备的四组之一。

1. 拖动时间轴检查 RGB 与 SAM3 叠加；时间同时显示采样帧、录制时间、原始源帧编号。默认按 10 Hz 从 30 Hz 录制抽取，约每组三秒 30 帧，整组 200 帧。
2. 在关键帧左键前景、右键背景；头、衣服、裤子和四肢要共同表达“整个人”，只点上衣可能只分出衣服。
3. 保存分段提示，设置终点。传播失误处另建分段；出画与返回分开处理。当前只支持一个人物 ID。
4. 运行 SAM3 分割，进程退出后抽查全程。点击 **确认已核查 · 导出 RGB-D 参考掩膜**，保存不可覆盖的参考修订。
5. 点击 **用当前参考重新评估实际选点**，完成后点击 **打开点集对照报告**；这一步只读取已保存的实际优化点，不重新加载人体模型。
6. `active-reference.json` 指向该修订，之前的分割与对照报告保留。编辑提示不会自动修改旧参考，必须重新分割、核查并导出。

本类 RGB-D 项目只在该页制作掩膜，隐藏视频人体重建和合成操作，防止误用普通视频的无标定流程。SAM3 与身体/MHR GPU 互斥仍由原有 OS 锁保护；自动化命令的独占锁同样有效。

## 运行

在 Studio 根目录，使用配置好的 standard Python 执行控制器；它会自动启动已有 Fast/SAM3 环境，不安装依赖。

```bash
PY=/run/media/hzb/Data/conda-envs/sam3d-body/bin/python
$PY studio/rgbd/rgbd_tracking.py prepare outputs/rgbd-sequences/某序列 outputs/depth-fusion/tracking-v1/某实验 --hz 10
$PY studio/rgbd/rgbd_tracking.py segment outputs/depth-fusion/tracking-v1/某实验
$PY studio/rgbd/rgbd_tracking.py track outputs/depth-fusion/tracking-v1/某实验 --steps 15
$PY studio/rgbd/rgbd_tracking.py evaluate outputs/depth-fusion/tracking-v1/某实验 --steps 15
```

准备阶段缓存当前帧 YOLO 框/17关键点，记录其实际耗时。分割阶段独立加载 SAM3 并退出。候选拟合不读取掩膜；`oracle` 仅指以 SAM3 掩膜限制测量点的离线对照，不是姿态真值。

运行目录不覆盖：重复跟踪需选择新的实验目录；不要删除原始录制来重新运行。手动参考更新后可再次 `evaluate`，会生成带参考哈希的新报告目录，不覆盖旧报告。若旧 oracle 使用不同参考，报告明确提示它只是旧拟合结果的重新落点评估。

## 算法和当前范围

- Fast384 身体模式，现有 TRT 和解码/MHR/中间预测编译缓存；固定形状、表情、骨长及手部，更新 25 个选中 MHR 姿态参数与 XYZ 平移。完整出画后重新初始化身份形状。
- 首帧、恢复、质量失败及每 1 秒关键帧运行 SAM + 60 步深度细化；普通帧由上一帧初始化，默认 15 步，每 5 步更新对应。
- 当前 YOLO 关键点经过 COCO17→MHR70 语义映射，置信度加权鲁棒重投影；不把关节中心直接拉到深度表面。
- 深度在原始有组织网格上 stride=2 采样、估法线，排除无效和深度跳变邻域。标定变换到彩色系，以最近真实 Z 投到 320×180 几何格；不填洞，不生成虚拟测量点。该尺寸不是网络输入分辨率。
- 根据模型可见顶点、当前人物框、局部 3D 距离和表面朝向寻找投影对应，最多 1200 对，按图像网格分散采样。当前未实现严格解剖部位分区，也未引入恒速度外推。
- 目标：点到面 + 少量点到点 + 当前 RGB 关键点 + 弱时间先验及官方参数边界。接受检查允许静止；检查对应数量、绝对残差、RGB 误差和合成代价退化。阈值是试验值，需要四组验证。
- 未检测到明确人物时 LOST、不拟合背景、不输出有效人体；失败帧 DEGRADED 并请求下一帧重新初始化。
- 两版关键帧使用同样无掩膜细化，只有普通帧选择是否用 SAM3 限制对应；应分开统计关键帧与普通帧，oracle 汇总内点率并非必然 100%。

## 输出与点坐标

```
某实验/
  inputs.json                 源录制/标定哈希、时间戳、源帧、YOLO、RGB 哈希
  project.json                与现有视频页兼容的分段点提示
  frames/                     去畸变 RGB，不是原始相机畸变网格
  reference_masks/            初次自动提示 SAM3 参考
  references/reviewed-*/      手工确认后的不可覆盖参考修订
  active-reference.json       当前手工参考指针（如已导出）
  network_keyframes/          冻结网络初值与实际网络耗时
  candidate-15/               不读 SAM3 的候选结果
  oracle-15/                  SAM3 限制对应的离线结果
    frames.jsonl              状态、关键帧原因、分阶段耗时/拟合信息
    points/000123.npz          实际优化对应及筛选前模型投影
    states/000123.npz          MHR 参数、相机平移、固定体型/表情、有效性
    complete.json             实验配置、输入/源码哈希、范围说明
  comparison-15*/
    report.html               可播放双栏点集视频与抽查图
    point_comparison.mp4      左无掩膜、右 SAM3 对照，展示末批实际点
    frames.csv                每帧所有批次统计，包含被拒绝尝试
    summary.json              指标、定义、参考来源
```

`points/*.npz`：

- `pixel_uv[N,2]`：**当前帧真实深度测量点**在全尺寸、去畸变 RGB 中的浮点 `(u,v)`，不是模型点投影。
- `target_xyz[N,3]`、`normal_xyz[N,3]`：彩色相机系、米与单位法线。
- `vertex_ids[N]`：对应 MHR 顶点；`batch[N]`：对应更新批次。
- `batch_step[B]`、`batch_used_steps[B]`：每批从哪步开始、真正参与几步优化。只记录进入优化器的批次，数量不足而未执行优化的候选不冒充实际点。
- `candidate_uv[M,2]`：距离/观测匹配前的模型候选投影，仅作筛选诊断，不算实际测量点。
- LOST 文件为空点集；被拒绝拟合仍保存实际参与的点，帧状态和有效性另列。

颜色：绿点=参考内，红点=参考外，青色=参考轮廓。视频为末批，CSV 为所有实际批次；同时提供唯一像素内点率，避免重复对应掩盖现象。

主指标是点的参考区域内比例、最差帧、边界 3 像素以外的外点比例。**不将点集的 IoU 当作分割 IoU，也不把高内点率当作全身覆盖或姿态正确的证据。** 自动 SAM3 传播仍需检查；分段外的空掩膜不是独立分割判断，单独标识、不混入主内点率。

计时明确区分解码/几何、拟合、接受检查、导出，补列缓存 YOLO 与网络的测得成本。记录过程本身有开销；缓存输入回放的成本估算不能替代实际相机端到端吞吐。每秒关键帧会造成延迟尖峰，需要后续优化与调度，不能仅拿普通帧拟合时间宣称 10 Hz。

## 四组离线验证结果（2026-11-06）

使用现有四组录制，每组按时间戳采样 200 帧。候选版与 SAM3 限制选点的对照版共 1600 帧；所有实际对应的坐标投影、单位法线、批次步数、状态和源帧编号通过完整性检查。

| 动作 | 普通帧实际点落在 SAM3 参考内 | 普通帧拟合中位数 | 普通帧含记录及观测成本估计 |
| --- | ---: | ---: | ---: |
| 双臂抬放 | 96.86% | 48.9 ms | 116.0 ms |
| 交叉与屈肘 | 96.77% | 47.7 ms | 116.7 ms |
| 转身与移动 | 97.88% | 47.5 ms | 116.9 ms |
| 遮挡与恢复（参考待核查） | 94.05% | 46.7 ms | 115.7 ms |

恢复序列的第 155、162–169 采样帧被标记为参考待核查：人物重新入画时，SAM3 可能只包含衣服或局部身体。已在第 170 帧补充分段全身提示，旧掩膜、旧对照和旧 oracle 结果保留。当前统计没有剔除这些低分帧，最差帧内点率为 41.69%，不能直接归因于跟踪算法；可在 GUI 手动修正后重新评估。该序列候选版 141 帧有效、57 帧 LOST、2 帧 DEGRADED；LOST 表示无可靠全身检测，并非独立判断画面中完全无人。

普通帧几何构建约 31 ms、拟合约 47–49 ms，记录本身约 25 ms；全帧包含关键帧的 P95 成本估计为 390–416 ms。当前尚未达到稳定在线 10 Hz，后续优先减少导出开销与关键帧阻塞。对照只验证测量点是否落在参考人体区域，不能替代姿态精度验证。

本机汇总报告：`outputs/depth-fusion/tracking-v1/report.html`。各组均包含 200 帧对照视频、每帧 CSV 和逐批次真实点集 NPZ。另有完全不存在 SAM3 参考文件的 3 帧 GPU 冒烟实验，确认候选路径可独立运行。Fast384 / Standard512 的原单帧优化 GPU 数值回归通过；新单元测试 6 项、既有深度测试 7 项、视频项目测试 5 项通过；GUI 已验证真实项目打开及手动参考导出后 QProcess 重新评估流程。
