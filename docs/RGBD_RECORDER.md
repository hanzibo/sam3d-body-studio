# 独立 RGB-D 数据采集（照片与连续流）

这是深度约束开发的第一个里程碑：先采集可重复使用的静态姿态集，再自动比较原始和深度校正结果。记录器只打开 Gemini 336L，不加载 SAM3、SAM 3D Body 或 Fast 模型，不运行分割和重建。

## 启动与拍摄

```bash
./launch_rgbd_recorder.sh
# 也可以直接继续之前的采集
./launch_rgbd_recorder.sh --session /path/to/recording-session
# 可选：安装独立桌面图标（不会替换 Studio 图标）
python3 scripts/install_desktop.py --recorder --desktop
```

1. 关闭 Studio 或其他程序中的相机预览。相机只能由一个采集进程使用。
2. 设置姿态数量，点击“新建采集”。左侧显示姿态清单和建议，可修改当前姿态说明。
3. 点击“连接相机”。上方为彩色，下方为深度伪彩；深度黑色区域没有有效测量。
4. 设定倒计时，摆好姿势后点击拍摄。Ctrl+Enter 拍摄，Esc 停止并释放相机。
5. 如需一人完成整组：勾选“自动依次拍摄”，设定换姿势间隔。程序从当前姿态依次拍到最后一张，每张先留出换姿势时间，再倒计时。
6. 提示保存成功后才算完成。重拍会创建新目录，旧版保留；中断后可“继续已有采集”。

自动采集在每张之后释放相机、导出数据，再为下一张重新连接。换姿势间隔从下一张相机就绪时开始，因此实际照片间隔还包含保存、重连和倒计时。这是离散 RGB-D 快照集，不是高帧率连续 RGB-D 视频。

拍摄期间不要在 Studio 中同时修改同一个姿态集。记录窗口会锁住这组数据，Studio 数据管理页禁止清理；关闭窗口或进程退出后系统会自动释放锁。

## 建议的一组数据

默认八个建议姿态：正面自然站立、双臂平举、双臂前伸、双肘弯曲、左右各转约45度、单臂抬高和侧身。可设置任意 1–100 张。

- 先拍摄双臂与躯干分离、无遮挡的基础姿态。
- 再拍摄双手靠近身体、双臂交叉和侧身等难例。
- 同一姿态可在两个距离重复拍摄，并把距离写入说明。
- 每张拍摄时保持静止、全身入画。避免截掉手腕、脚和头顶。
- 深度有效比例是整幅图像统计，不能当作人体区域深度质量或骨骼精度。

## 保存位置和内容

默认目录：`outputs/rgbd-sets/recording-<时间>/`，整个目录被 Git 忽略。

```text
recording-<时间>/
  pose_set.json                 # 当前姿态、说明、当前样本、重拍历史
  .recorder.lock                # OS 锁；文件保留不代表进程还在运行
  samples/
    pose-001/<拍摄时间>/
      rgb_raw.png               # 原始彩色
      rgb.png                   # 去畸变彩色，后续模型输入
      depth_raw.png             # 原始 uint16 深度；单位比例见 camera.json
      rgbd.npz                  # depth_m / xyz_m，配准至彩色相机，单位米
      camera.json               # 内外参、畸变、深度比例、帧号及时间戳
      depth_preview.png         # 仅预览，不能作为真实深度输入
      scene.ply                 # 相机系点云
      worker.log                # 相机采集日志
```

RGB-D 样本使用 `studio_rgbd_v1`，姿态集使用已有 `studio_pose_set_v1`。在 Studio 第三个标签页的“打开样本集”选择整个采集目录即可；也可以“打开已有样本”选择单张拍摄时间目录。之后再逐张标注 SAM3 前背景点、分割人体并批量运行。

仅完整导出、退出码为零且 RGB-D 时间差符合记录阈值的样本会加入当前姿态。取消或失败时不替换旧照片。未完成的目录可在确认不用后通过数据管理清理整个样本集，或手动处理。

## 后续开发边界

本里程碑没有修改网络、TensorRT、MHR 姿态，也没有执行深度校正。后续顺序：

1. 用此数据集测试三维平移校正，保留原始与校正结果。
2. 增加 GUI 对照、留出点检查、批量指标及独立求解耗时。
3. 证明收益后研究体型标定、双臂姿态精修与同步实时 RGB-D。

## 连续 RGB-D 视频流录制

同一启动程序新增 **“连续 RGB-D 录制”** 标签页，照片采集保留在第一个标签页。两个模式使用相机时互斥；Studio 等其他程序也应先释放相机。

1. 输入本段的**数据名称**，如 `双臂抬放_正面_2米_01`。每次创建独立的“名称＋时间”目录，重复名称不会覆盖旧数据。
2. 选择动作方案：双臂抬放、交叉屈肘、转身移动、遮挡恢复或自定义。设置时长（5–300 秒）、开录倒计时和目标保存帧率（30/15/10 FPS）。可填写替换中段动作提示的备注，说明会保存到清单。
3. 点击**连接并预览**，调整头脚完整入画。此时不保存数据；不满意可以直接断开。
4. 点击**倒计时开始录制**（Ctrl+Enter），按大字倒计时和动作提示进行：开头静止 2 秒、中段缓慢动作、回到起始姿态、最后保持静止。动作阶段切换可用提示音提醒。
5. 等待自动结束，或点击**结束并保存** / Esc 提前结束。保存队列清空后才显示最终保存帧数、实际帧率、写入丢帧和时间差剔除数。录制前取消不会创建数据目录。
6. 在左侧最近录制列表双击打开数据目录，或点击下方打开目录。可继续用新名称录下一段。Studio **数据管理**将其归入“连续 RGB-D 序列”，活动录制目录禁止删除。

**预览约 5 FPS，与录制帧率独立。** 目标 30 FPS 不保证硬件一定达到：以逐帧时间戳、实际保存帧率和丢帧计数为准。写入使用容量受限的后台队列；来不及写入会明确统计丢帧，不无限占内存。只保留 RGB-D 时间差不超过 20 ms、设备时间戳递增的帧；10/15 FPS 主动限速不计为写入丢帧。距离与全图有效深度比例不是人体精度指标。

### 连续序列格式

```text
outputs/rgbd-sequences/<自定义名称>__<时间>/
  sequence.json              # 名称、状态、动作时间表、目标/实际帧率、丢帧、设置
  camera.json                # 原始 RGB / 深度内参、畸变、D2C 外参、设备和流配置
  frames.jsonl               # 每对成功写入帧的路径、SDK 帧号/时间戳、接收时刻、深度比例
  rgb/000000.jpg             # MJPEG 相机原始压缩数据直存；其他格式使用无损 PNG
  depth/000000.png           # 原始 uint16 深度，无损 PNG
  .recorder.lock             # 录制期间 OS 锁，阻止数据管理删除
  worker.log
```

Gemini 当前彩色流为 MJPEG：直接保存相机给出的 JPEG 字节，不解码后二次有损编码。相机本身已有 JPEG 压缩；这里不宣称它是无损传感器 RGB。其他彩色格式回退为无损 PNG。深度始终为无损 uint16 PNG。

连续录制保存的是**两路原始网格**，没有逐帧生成 `rgbd.npz` 和 PLY，不能直接把原始深度当作彩色相机坐标系下的深度。这样将配准与点云计算移出采集热路径，原始测量仍完整保留。米制深度为 `raw_uint16 * depth_scale_mm / 1000`（比例随帧保存）。`host_monotonic_ns` 是接收时刻，不是曝光时刻；RGB/深度同步检查使用 SDK 时间戳。`relative_time_s` 是相对实际开录的单调接收时间。

后续跟踪可使用 `RGBDSequence` 读取，并按需进行与静态样本相同的离线配准：

```python
from rgbd_sequence import RGBDSequence
sequence = RGBDSequence('/absolute/path/to/named-sequence')
rgb_raw, depth_raw, metadata = sequence.read(0)
rgb_rectified, depth_m, xyz_m, metadata = sequence.read(0, registered=True)
# depth_m / xyz_m 对齐至去畸变彩色相机，单位米，x右/y下/z前。
```

状态 `completed` 表示正常完成；`stopped` 表示用户提前结束；`error/interrupted` 表示异常。异常数据默认不作为完整输入，需显式 `allow_partial=True` 读取已提交帧。强制断电/杀进程可能留下 `recording` 状态及孤立文件；只认 `frames.jsonl` 中完整提交的帧，不将半写入文件当作数据。

录制耗时和 JPEG／深度 PNG 的实际体积取决于场景。开始前至少保留 1 GiB；可用空间不足 512 MiB 时停止并保存。短序列也可能占数百 MiB，先用 20 秒测试确认实际帧率与体积。连续序列整个目录仍在 Git 忽略范围内。

### 本机验收（2026-11-06）

Gemini 336L 实际连接测试：彩色 1280×720 MJPEG / 深度 848×480 Y16，两路 30 FPS。20 秒录制保存 599 对帧，实际约 29.96 FPS，写入队列丢帧 0，时间差剔除 0；RGB-D 时间差最大 1 ms，彩色帧间隔最大 34 ms，数据约 216.5 MiB。全部 599 对图片已解码检查，深度保持 uint16，三路时间戳严格递增。此结果只证明本次相机场景下的采集保存链路，不是人体跟踪或重建测速。测试数据名称带“验证…非动作数据”，不会与用户正式动作序列混淆。

照片采集回归、连续录制协议回放、提前结束保存、预览取消与相机重开均通过。测试脚本：`tests/rgbd_stream_recorder_gui.py --hardware --duration 20`；数据格式测试：`python -m unittest discover -s tests -p 'test_rgbd_sequence.py'`。
