# 手部实验：手动框选、自动找手与双手序列

重启 Studio 后进入最后一个标签页“手部实验”。该页面使用官方原生 hand 分支，不调用身体解码器。手动模式每次处理一只手；自动模式使用 WiLoR 的专用手部检测器寻找左右手，并将两只手的裁剪作为一个批次重建。现有身体页的启动方案不会改变手部页配置。

## 使用

1. “打开图片”或“使用第一页照片”，在“框选单只手”视图拖动矩形，包含整只手及少量手腕；选择实际的左右手。
2. 裁剪比例默认 0.9，与官方手部分支预处理一致。它乘在框的宽高上，再扩展为正方形，最后仿射采样至 512×512；小于 1 会缩小裁剪范围。若指尖被切掉，扩大手框或提高比例。实际网络输入可在“实际裁剪”页检查。
3. 点击“应用并加载”，自动释放当前空闲身体 / MHR 实验室模型。正在推理、视频、SAM3、RGB-D 任务期间拒绝切换。加载后可对当前手框预热三次，再点击“重建手部”。
4. 查看可旋转的三维手部（可开关骨架）、原图投影以及真实裁剪图。“打开结果目录”查看导出。
5. 返回身体页预加载前，点击“释放 / 取消”。取消会停止整个独立进程作用域，释放模型；下次需重新加载。

默认基线为原生 PyTorch 编码器 FP16，手部解码器和 MHR FP32，512 输入；现可在加载前选择 TensorRT / 编译 / CUDA Graph，参见 [手部加速说明](HAND_ACCELERATION.md)。仍加载完整共享 checkpoint，**跳过身体计算不代表仅加载手部权重**。独立进程通过 Studio 的 GPU 独占锁与身体 / MHR / SAM3 工作进程互斥，并设置 7 GiB 主存及 2 GiB swap 上限；不控制其他应用的显存。

## 相机内参

“使用照片 / Gemini 内参”开启时，优先使用从第一页传入的照片元数据，或图片同目录的 `camera.json`。对于 Gemini 录制的 `frames/xxxxxx.jpg`，自动读取上一级数据集的 `manifest.json → profile.intrinsics`。读到照片内参时自动勾选开关。固定 Gemini 预设仅在图像尺寸匹配时适用；无可用内参时使用对角线焦距估计。实际来源写入报告。

当前 WiLoR 录制目录的 manifest 表明数据为 **RGB only**；本页没有使用深度，也没有做深度拟合。

## 输出

每次结果位于 `outputs/hands/<时间>/`，在“数据管理”中按完整目录管理：

- `source.png`：GUI 固定下来的本次输入，防止源文件被外部修改。
- `input.png`、`crop.png`：原图、真正输入网络的 512 裁剪图；左手裁剪图是镜像图。
- `hand.ply`：单手局部网格，米制，腕部开放截面，非水密模型。
- `hand.npz`：单手网格、23 个 MHR 骨架节点及连线、旋转、原图投影坐标、相机平移与内参、原始手框和仿射矩阵。23 个节点包含 MHR 辅助 / 末端节点，不等同于常见的 21 个手部关键点。
- `raw_hand.npz`：官方手部分支原始张量，默认包含完整 MHR 载体数据；开启“最终仅生成手部网格”时顶点只保留手部，并由 `pred_vertex_ids` 标注原始 MHR 编号。骨架仍保留完整依赖；未预测的身体部分不可当作完整人体结果。
- `request.json`、`report.json`：请求、来源、权重哈希、上游提交、执行次数与计时。预热任务保存 `warmup.json`。

`hand.npz` 的 `vertices/joints` 为相机轴方向下的局部数据（x 右、y 下、z 前），加上 `camera_translation` 才是相机坐标。`global_rotations` 为以 CV 基表示的 MHR 全局旋转，不是机械手关节角。`canonical_vertex_ids/canonical_joint_ids` 对应右手载体索引；`joint_ids/joint_names` 表示实际左右侧。左手使用镜像图经过右手分支，然后反射几何、平移、旋转并翻转三角形绕序。**左手 raw_hand.npz 中原生参数仍是规范右手参数**，不能直接充当左手 MHR 参数。

手部网格根据 `r_wrist` 后代关节的累计蒙皮权重 ≥ 0.5 提取，只保留三个顶点都在区域内的面：当前 2321 顶点、4613 三角形。未改动上游仓库。

## 验证范围

真实运行了既有人体照片的左右手，以及用户 Gemini 单手 / 双手录制中的代表帧。GUI 验证覆盖真实 GPU 加载、三次预热、重建、实际 OpenGL 三维与叠加显示、照片内参、身体加载拦截、SAM3 排他锁与进程释放。

无界面手部分支预热后约 175–177 ms；实际界面测试约 178–212 ms（显示渲染会共享 GPU），均含裁剪、输入传输、编码、手部解码、MHR 和 CUDA 同步，排除输出复制、导出及界面渲染。单次任务加导出约 0.29–0.40 s；不是完整数据集均值或实时流帧率。每次实测为 `body=0, hand=1, backbone=1`。

原生投影与导出网格重新投影差异低于 0.001 px，只验证坐标计算一致性，**不是与真实手部的重建误差**。没有手部三维真值，当前为手动框选的功能与可视化验证；已增加自动检测、左右标签连续性及双手批次输出；尚未接实时相机流。左右标签连续性只辅助框的身份关联，不是三维姿态跟踪或平滑。

测试：`tests/test_hand_geometry.py`、`tests/hand_lab_gui.py`。后者需要本地模型和 Gemini 样本，会真实加载 GPU；可通过 xvfb-run 运行，无需操控用户桌面。此次报告与截图保存在 `/run/media/hzb/Data/experiments/hand-lab-20261112/`。

## 自动找手

1. 打开图片，勾选上方“自动找手”，默认检测置信度 0.40、裁剪比例 1.10。可以先点“仅检测手框”检查左右标签、框和置信度。
2. 应用并加载，点击预热，再重建。自动模式不要求手工画框；仍保留关闭自动模式后的手工框选。
3. 每帧检测，最多输出同一个人的左、右各一只手。两只手作为批量大小 2，共调用一次编码器与一次 hand 分支；不是将双手挤进一张裁剪图。未检测到的手立即清空，不沿用上一帧网格。

专用检测器为 WiLoR 发布的 `detector.pt`（YOLOv8m-Pose，left/right 两类、21 关键点）。本实现只使用其框、左右类别和置信度，不将检测器的关键点作为 SAM 网络提示，也不加载 WiLoR 三维模型或 MANO。普通 COCO YOLO26 Pose 的 17 个身体关键点不能直接替代本检测器。当前限定已验证的检测器 SHA256，其他权重会被拒绝，避免静默加载错误模型。

可通过 `config/local.json` 的 `hand_detector_checkpoint` 设置本地权重路径；示例默认 `models/hands/detector.pt`。权重不随源码发布，许可见 `THIRD_PARTY_NOTICES.md`。目前本机复用 Data 盘既有 WiLoR detector。

自动结果使用 `hands.npz` 保存相机坐标下的合并网格、左右手框/得分及各手原始局部数据；合并场景的 `camera_translation` 为零，各手局部网格需要加各自平移。单手原始参数的左右镜像约定与上文一致。PLY 导出为相机坐标。

## 双手逐帧重建

进入手部实验内的“连续序列”子页，打开包含 `manifest.json`、`timestamps.jsonl` 和 `frames/` 的 Gemini 录制目录。目录必须录制完成，帧数、时间戳和内参须有效。此功能支持当前 RGB-only 录制，不要求深度。

预加载后点击“逐帧自动重建”；默认逐帧，也可设置抽帧间隔。“左右标签连续性”利用相邻框的位置/重叠减少左右类别翻转；超过约 0.5 秒未观察到的历史失效，不对遮挡手外推，不保证交叉时的身份正确。多个人物不在当前支持范围内。

结果可切换原图叠加 / 三维场景，用时间轴逐帧查看或连续播放，也可导出叠加 MP4。任务中“释放 / 取消”会终止独立工作进程，保留已输出帧但标记为未完成；不可作为完整结果回放。

默认保存到 `outputs/hand-sequences/<时间-来源>/`，本机通过 `hand_sequence_outputs` 配置保存到 `/run/media/hzb/Data/experiments/sam3d-hand-sequences/`。默认项目 outputs 可由数据管理页管理；配置到外部 Data 目录的结果请用“打开结果目录”管理，不自动扩展数据管理页的删除边界。

每份结果包含：

- `sequence.json`：源目录、内参、抽帧/检测选项、完成状态和汇总。
- `frames.jsonl`：每帧原始检测、选中左右手、缺失侧、计时及网格路径。
- `frames/*.npz`：逐帧相机空间双手网格、骨架、原生参数等。
- `summary.json`、`timings.csv`、`timing-groups.json`：整体及按检测手数分组的计时。分组统计去掉各批量大小最初三次，GPU 子阶段嵌套在重建时间内，不可重复相加。
- `overlay.mp4`：原图与双手投影的离线合成。源图仍从原始录制读取，移动或删除原始录制会影响 GUI 回放。

测试增加 `tests/test_hand_automatic.py` 和 `tests/hand_automatic_gui.py`。完整两组录制验证输出位于 `/run/media/hzb/Data/experiments/hand-auto-20261112/full/`。计时为离线推理/读写范围，不是实时相机或包含视频合成的 FPS；没有标注手框及三维真值，检测到手数不是检测准确率。

## 相机实时

现支持 Gemini 实时预览、自动找手、手部重建与同步原图投影 / 三维显示。使用方法、加速选项和计时口径见 [HAND_LIVE.md](HAND_LIVE.md)。

## 界面布局

启动方案位于顶部可折叠卡片；编译、Graph 与反馈优化收在“高级加速设置”。加载 / 释放与状态统一放在方案下方。照片相关操作集中在左侧，右侧保留大预览；序列 / 实时页自动隐藏照片侧栏。“实际配置与任务报告”默认折叠，可展开查看完整后端配置。较矮窗口可滚动左侧操作区。
