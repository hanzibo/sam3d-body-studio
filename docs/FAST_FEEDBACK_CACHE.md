# Fast 关键点反馈缓存

2026-11-08：默认启用到 Studio Fast 后端。此优化不减少六层解码器、中间人体预测次数或关键点数量，不改权重、引擎及数值精度。

## 改动

- 一次人体解码调用创建一个临时缓存。默认三次中间预测时，五次反馈中仅计算三次图像采样/二维位置编码/三维位置编码，另两次复用。
- 即使复用采样结果，每层仍将反馈加到该层的新 Token 上；不会跳过反馈累加。
- 两类大数组（Token 和位置附加项）各由复制两次改为一次，去掉只读坐标/深度的冗余克隆。
- 每次解码、每张图像、每个人、每轮交互提示均重新建缓存；训练、有梯度、双向更新及不支持的布局走原实现。
- 投影仍在每次新的中间人体预测中执行。本轮未改融合预测核心，也未实现关键点专用 MHR 蒙皮。

实现位于 `studio/body/fast_feedback.py`，通过运行时适配接入 `studio/body/fast_worker.py`，不修改上游仓库。缓存键使用本次解码中保留引用的预测对象身份，不按视频帧号或上一帧内容复用。

`inference.json` 的 `feedback_cache` 记录启用状态、版本和最后一次解码的实际计算/命中次数。正常三次反馈方案应为 `computations=3, hits=2`。已加载的旧进程需先释放模型，再应用并预热。

开发对照可在启动时设置 `BODYSTUDIO_FEEDBACK_CACHE=0`，回到上游原反馈路径；不改变用户保存的启动方案。

## 验证方法

- `tests/test_fast_feedback.py` 从本地上游 AST 提取真正的两个反馈函数，比较逐层结果，检查输入不被原地修改。
- 覆盖重复姿态、换图、无梯度/有梯度回退、批量、额外提示行、越界/负深度点及不同裁剪坐标约定。
- 真实 GPU 使用同一已加载模型切换原始/缓存路径，预热后按 ABBA/BAAB 顺序交替测量。完整推理计时包含检测、裁剪、网络及 CPU 输出；不包含加载、文件读写、GUI 和渲染。
- CUDA 事件分项单独测量，包含流等待和主机调度空隙，不能等同于纯核函数活跃时间。
- 质量核对使用原测速图片和已有 12 姿态集，并切换 3/2/1/0 次中间预测、掩膜和相机内参。检查模型输出差异，不把差异当作相对真实人体的精度误差。

复现命令（使用配置中的 Fast Conda Python）：

```bash
python -m unittest discover -s tests -p test_fast_feedback.py -v
python scripts/benchmark_fast_feedback.py \
  --image outputs/gui/20261103-174926-349375/input.png \
  --poses outputs/rgbd-sets/recording-20261106-135615-851252 \
  --output outputs/profiling/feedback-cache-NEW --runs 60
```

该诊断脚本目前复用本机原部署的 `/home/hzb/Work/fast-sam3d-body-deploy/run.py` 加载器；不属于通用安装入口。Studio 正式运行不依赖该外部脚本。512 验证添加 `--image-size 512`。所有测试产物保留于已忽略的 `outputs/`，不会提交真人图片或模型。

## Fast384 结果

RTX 4060 Laptop 8GB；身体模式；骨干/YOLO TensorRT；解码器/MHR/中间预测编译；三次中间预测。两种路径各预热 10 次，正式交替测量各 240 帧。

| 项目 | 原路径 | 缓存路径 | 差值 |
| --- | ---: | ---: | ---: |
| 完整推理均值 | 65.407 ms | 63.876 ms | 节省 1.531 ms（2.34%） |
| 完整推理中位数 | 64.781 ms | 62.647 ms | 节省 2.134 ms |
| 完整推理 P95 | 70.136 ms | 72.679 ms | 增加 2.543 ms |
| 反馈段均值（单独插桩） | 4.985 ms | 3.093 ms | 节省 1.892 ms（37.95%） |
| 解码器均值（单独插桩） | 23.078 ms | 21.037 ms | 节省 2.042 ms |

首轮各 120 帧复测为 65.084→63.066 ms，反馈为 4.880→3.028 ms。两轮均值均改善；完整推理 P95 未改善，因此不能宣称抖动或最慢帧已优化。不要与历史不同运行的 63.18 ms 直接作差。

13 张输入，以及额外的预测次数/掩膜/内参对照中，最大单坐标差：

## Fast512 兼容验证

同一脚本使用 512 引擎，仍保持三次中间预测与所有编译，每种路径预热 10 次、正式交替测量各 80 帧。完整推理均值 93.061→87.830 ms；反馈段 5.819→3.625 ms；解码器 24.197→21.066 ms。整网时间还受检测和调度波动影响，这一结果不代表每帧都固定节省 5.23 ms。

同样检查了 13 张输入和预测次数/掩膜/内参切换。最大顶点单坐标差 0.001789 mm，三维关键点单坐标差 0.001311 mm，相机平移分量差 0.000954 mm，二维投影差 0.015625 像素。原始结果位于 `outputs/profiling/feedback-cache-512-20261108/report.json`。

各基准目录保存 `fast_feedback-tested.py`，其 SHA-256 与报告中的 `adapter_sha256` 对应。最终源码补充了上游来源/许可证文件头，数值实现与测试快照相同；后续测试会自动保存当时源码。`studio/body/fast_feedback.py` 的适配算法按 SAM 许可单独标注，原创测试和诊断脚本采用仓库默认许可。

本次未对实时相机帧率、完整手部精修模式或所有未编译组合开展性能评测，不据此承诺这些路径的帧率。
