# SAM 3D Body Studio

## 打开与使用

双击桌面 **SAM 3D Body 人体重建 / SAM 3D Body Studio** 图标。关闭旧窗口后重新打开，才能使用更新后的界面。

1. 选择顶部启动方案，按需展开“高级设置”，再点击“应用并预热”。
2. 等待模型已就绪。设置区自动收起，留出图片和 3D 预览空间；点击“启动方案设置”可以再次展开。
3. 点击“选择图片…”、拖入图片，或“载入示例”。建议使用清晰的单人全身照片；多人时在左图框选目标。
4. 点击“开始重建”。网格生成后立即显示，可旋转、缩放和导出；图像对照在后台生成。

未提前预热也可点击重建，但首次等待包含模型加载和预热。模型常驻后连续多张照片复用。释放模型、取消计算或关闭窗口后，需要重新加载。

## 启动方案

默认“演示最快”：Fast、身体模式、384、骨干与检测器 TensorRT、三个编译开关全部开启。它适合身体姿态演示，手部独立精修关闭；384 可能损失精度，尚未做带真值的数据集精度评测。

| 选项 | 含义与限制 |
| --- | --- |
| 实现 | Fast 或标准版（已有 ComfyUI 实现），使用各自的独立 Conda 环境 |
| 身体＋手部精修 | 不勾选为身体快速模式，仍输出完整网格；勾选后增加手部精修 |
| 网络分辨率 | Fast 支持 384 / 512。384 目前仅支持身体模式；完整模式请选择 512。此项不是相机分辨率 |
| 骨干执行 / 检测器执行 | 可分别选 TensorRT 或 PyTorch；关闭 TensorRT 后使用已有原始权重，不静默回退 |
| 解码器编译 | 是否使用已部署的 torch.compile 加速路径 |
| MHR 编译 / 中间预测编译 | 高级设置中的独立编译开关，便于对照；首次编译可能较慢 |
| 预热次数 | 每个输入布局预热 1–30 次，只预热当前所选身体/完整模式 |
| 预热布局 | 上传示例、相机尺寸，或两者；相机尺寸使用 1280×800 的示例输入，不会为预热打开相机 |

标准版固定 512，TensorRT 和上述 Fast 编译选项禁用。Fast 固定 FP16 骨干、FP32 解码器；选择 PyTorch 骨干时骨干本身不编译。MoGe 不启用。Fast 目前只重建一个检出人物，框选用于选择人物，实际裁剪使用 YOLO 检测框。

内置“演示最快”“身体 512 对照”“完整人体 512”“关闭编译对照”“关闭 TensorRT 对照”“标准版身体”方案。“保存方案”会将当前设置以自定名称保存到 `profiles/`；支持导入、导出 JSON，关闭窗口会记住最后的有效设置。

已经加载模型时，修改设置不会立即重启。此时重建、同图测速和相机自动重建暂时禁用，点击“应用并预热”会释放旧模型再加载新方案；“恢复已加载方案”可撤销尚未应用的修改。加载、推理和拍摄倒计时期间锁定设置，防止显示选项与实际模型不一致。两个版本不会同时常驻 GPU。

## 同图测速与历史

加载同一图片并固定人物框后，点击“同图测速…”。默认额外预热 10 次、正式测量 50 次，可调整为预热 1–30 次和测量 1–200 次。界面显示进度、平均值、中位数与 P95，并用最后一次结果显示 3D。

测量范围是内存中的 RGB 图像，经检测、裁剪、模型到 CPU 输出，包含 CUDA 同步；排除权重加载、图片解码、网格导出、3D 显示和后台对照图。测速前会停止已有后台对照渲染，减少干扰。“3D 就绪”另行统计从点击到显示网格的等待时间，不能与模型毫秒数混用。

每次结果保存完整启动配置、配置 ID、图片 SHA256、人物框、实际编译状态和引擎验证信息。“运行历史 / 导出”中可对照已完成任务，双击查看完整报告，导出 CSV。比较时请使用相同图片与人物框；单次重建不提供中位数/P95。预热次数和布局也计入配置 ID。

点击“取消”会终止当前模型进程。未完成测速的 `benchmark.json` 保留已完成样本并标记 `complete: false`，不会计入完成历史；重新运行需要加载模型。

## Gemini 336L 倒计时拍摄

1. 连接相机，点击左侧“打开相机 / 重拍”，等待 1280×800、30 FPS 的 RGB 实时预览。
2. 固定相机，让头、手和脚完整入画；预览中可以框选目标人物。
3. 选择 3 / 5 / 10 / 15 秒延时（默认 10 秒），点击“拍照并重建”，离开电脑摆姿势。
4. 到时保存原始分辨率照片，释放相机，再用已选方案重建。取消“拍照后自动重建”可只拍照，再手动开始重建。

实时预览不保存照片。“取消”在倒计时中只取消预约、恢复预览；“关闭相机”停止采集。相机异常时清除实时画面并禁止使用旧帧重建；检查连接后重新打开。模型预热与相机使用不同进程。

照片保存在 `outputs/camera/日期-时间-微秒/`，包含 `photo.png` 和 `camera.json`；拍照后自动重建时元数据复制到结果目录。

当前只使用 RGB 单张图像。相机内参保存在记录中，但没有加入深度先验，也没有标定人体真实尺度。遮挡和头脚出画会影响预测。

## 3D 预览与结果

- 左键拖动旋转，滚轮缩放，中键拖动平移。
- “正面 / 背面 / 左侧 / 右侧”切换视角，“复位”恢复中心和缩放。
- 可开启线框或自动旋转，使用“另存网格 PLY…”导出。

预览自动居中并竖直显示，不改变导出模型的原始坐标。切换输入或开始下一次重建会取消旧对照图，防止显示过期结果。对照图生成失败不影响已完成网格。

每次任务独立保存至 `outputs/gui/日期-时间-微秒/`：

| 文件 | 内容 |
| --- | --- |
| input.png | 本次 RGB 输入快照 |
| request.json | 输入路径、人物框、启动方案与配置 ID |
| person_00.ply / person_00.npz | 网格，以及顶点、关键点、姿态、体型等数组 |
| inference.json | 实际配置、模型计算与 3D 就绪耗时、编译和引擎信息、输入哈希 |
| benchmark.json | 测速逐次采样、完成状态与统计（仅测速任务） |
| reconstruction.jpg / preview.jpg | 后台图像对照与缩略图 |
| comparison.log / run.log | 对照图与运行日志 |

加载方案快照保存在 `outputs/sessions/`，完成历史保存在 `outputs/gui/run-history.json`。关闭窗口会停止模型、相机及后台渲染进程。

## Gemini 真实内参开关

相机区域的“使用 Gemini 真实内参”默认开启，并记住上次选择。切换对下一次重建或同图测速生效，不需要重载或重新预热模型；已生成网格仍标明当时实际使用的内参。拍摄倒计时和推理期间锁定开关。

- 实时拍照、载入旁边有 `camera.json` 的历史照片：优先使用照片元数据中的 RGB 内参。
- 没有元数据、尺寸为 1280×800 且已配置固定标定的照片：使用自行配置的 Gemini 336L 固定内参，并提示“请确认照片来自此相机”。其他相机拍摄的同尺寸图片请关闭开关。
- 没有元数据、尺寸不是 1280×800 的图片：不套用固定内参，界面明确提示使用默认估计。项目自带示例因此仍使用默认值。
- 照片元数据损坏或分辨率不匹配：禁止开启真实内参后的重建。可修正元数据，或关闭开关使用默认估计。
- 关闭开关：使用模型原有的默认估计内参，便于同图对照。

可选固定参数保存于 `config/gemini336l_rgb.json`，必须使用你自己的相机标定。未配置该文件时使用默认估计并给出提示。相机新拍照片仍以采集时 SDK 返回的内参为准；不要按网络 384/512 裁剪尺寸缩放这些原图参数。

两种后端及图像对照都使用同一完整矩阵。`request.json` 保存开关、所选参数和来源；`inference.json` 保存实际使用的矩阵与来源；历史列表和 CSV 可区分真实/默认内参。内参是每次输入的选项，不计入模型启动方案 ID。

内参没有加入深度观测或畸变校正，不代表人体真实尺寸已经标定。



## 骨架、角度与动作录制

重启桌面图标即可使用。模型预热和相机连接流程不变。

结果区新增三个独立开关：

- **网格**：显示人体表面；关闭后可以只看骨架。
- **骨架**：显示 MHR70 中的身体、手腕与脚部连线；绿色为人物左侧，橙色为右侧。当前不绘制手指骨架，也不是 127 个 MHR 关节的完整层级图。
- **肘膝角度**：结果区显示左右肘、膝的三维三点夹角，伸直约 180°。这些是关键点几何夹角，不是解剖学屈曲角或机器人局部关节旋转。遮挡和模型估计误差会影响读数。

单张图片和连续推理均支持骨架、角度。彩色叠加中的骨架坐标对应同一推理输入帧；3D 中可以旋转查看。开关不需要重新预热，也不改变原始预测。仅隐藏网格不会省掉后端的网格计算。

### 连续动作录制

1. 应用并预热方案，打开相机，然后开始连续推理。
2. 点击结果区的“开始动作录制”。录制期间可以切换显示层。
3. 点击“停止动作录制”；也可以直接停止连续推理，自动结束录制。
4. 等待显示“已保存”，再点击“打开动作目录”。关闭窗口也会结束并等待写盘。

数据保存在 `outputs/motions/时间戳/`：

| 文件 | 内容 |
| --- | --- |
| `session.json` | 数据定义、关键点名称、连接、角度口径、启动方案、ROI、相机元数据、帧数、失败数和保存状态 |
| `frames.jsonl` | 每行一个 pose/gap 事件；成功帧含 70 个二维/三维关键点、127 个关节位置与全局旋转、相机平移、可用的 MHR 姿态/体型参数、内参和时间戳 |
| `angles.csv` | 每个成功帧的左右肘膝角度、时间和模型耗时 |
| `keypoints.csv` | 每成功帧 70 行，包含关键点名称、模型坐标和输入图像像素坐标 |

JSONL 可以逐行读取为 JSON；不需要一次把完整动作加载到内存。关节旋转矩阵保留在 JSONL 中，CSV 提供关键点和角度的便捷访问。

录制的是实际成功推理帧，保持原始可变时间间隔，既不补帧，也不保存 RGB 视频、深度或每帧网格。时间戳来自主机接收相机帧的时间，不等于相机曝光时间。人物消失会写入 gap 并清除旧骨架；仍按单人选择工作，没有人物身份跟踪或平滑。

写盘在线程中进行，队列有上限。发生写盘错误或队列溢出时明确停止录制并显示错误，不把数据缺失标成成功。意外断电后可检查 JSONL 中已经刷盘的完整行；`session.json` 的 recording 状态表示未正常结束。

### 导出单帧骨架

单图重建后，或停止连续推理后，点击“导出当前骨架…”，选择父目录。程序在其下创建时间戳子目录，并输出同样的 JSONL、CSV 和描述文件。单帧导出的时间是导出时间；连续流录制中保存的才是实际主机接收时间。

模型坐标沿用后端输出：x 向右、y 向下、z 向前。相机平移单独保存，不要将模型坐标直接当成世界坐标。70 个关键点和 127 个 MHR 关节不能混用编号。

## SMPL 转换与 MLP 平滑

在“启动方案”中选择 **SMPL 身体低延迟** 或 **SMPL 身体＋MLP平滑**，然后应用并预热。也可单独勾选“SMPL 转换（24 关节）”与“MLP 平滑”。标准版和 Fast 版均支持，原有默认方案仍关闭此功能。模型路径留空即可，已自动使用 `assets/smpl/SMPL_NEUTRAL.npz`（来自用户提供的 SMPL v1.1.0 neutral 模型，保留前 10 个形状系数；不含表面 LBS 数据）。原压缩包与 pickle 保留。

单张重建后可切换“SMPL 骨架”标签，用鼠标旋转、缩放观察。连续推理显示方式可选“SMPL 身体骨架预览”。“SMPL 预览”下拉框切换原始当前帧和 MLP 平滑中心帧，旁边显示处理耗时与平滑来源帧/延迟。SMPL 预览只画 24 关节骨架；原有 MHR 网格和 RGB 叠加仍使用原始 SAM 输出。

MLP 处理最近 5 个推理帧的规范化关节，训练目标是中心帧，因此历史满时约落后当前 **2 个推理帧**，不是 2 个相机曝光帧。开始时用首帧补齐；重启连续推理、出错或输入时间间隔超过 0.5 秒会清空历史。单张图没有时间序列，平滑结果仅供静态观察。平滑的是关节位置，**不产生平滑后的 SMPL 旋转或姿态参数**，也不保证严格骨长约束。需要低延迟时选原始 SMPL；MLP 更平滑是否值得额外延迟需实测。

动作录制和当前骨架导出新增：

- `smpl_parameters.csv`：当前帧 global_orient（轴角弧度）、21×3 body_pose（轴角弧度）和 10 个 betas。
- `smpl_joints.csv`：raw/smooth 两组 24 关节、名称、根相对坐标、CV 模型坐标、来源帧/时间与 lag_ms。
- `smpl_angles.csv`：两组肘膝三点夹角（度，伸直约 180°）。
- `frames.jsonl`：同时保留原始 MHR、SMPL 参数、全局旋转、原始/平滑关节和时间信息。全局旋转始终是原始当前帧旋转。

SMPL 显示采用 CV 轴方向，并把骨盆锚定到 MHR 双髋中点；不是重新估计的世界坐标或独立根平移。Gemini 内参继续作用于原有推理/投影；这两个模块没有使用深度图。此功能提供姿态数据，机器人仍需额外的坐标标定、双臂重定向和逆运动学。

## 身体中间预测次数与 One Euro（2026-11-03）

“身体中间预测”在启动方案中可选 3/2/1/0 次，仅适用于 **Fast 身体模式**。分别在解码层索引 `0,1,2` / `0,2` / `0` / 无中间层执行人体回归，最后一层始终预测；不是裁掉 Transformer 层。原有方案默认 3 次不变。修改后点击“应用并预热”，已加载方案与新参数不一致时会阻止直接重建。0 次仅供实验，可能明显改变姿态。

新增预设：

- **SMPL 身体＋One Euro**：原来的 3 次身体反馈，加因果位置滤波。
- **实验：身体反馈2次＋One Euro**：减少一次中间回归。
- **实验：身体反馈1次＋One Euro**：仅保留首层中间回归。

启用 SMPL 后勾选 One Euro，设置参数并预热。默认最小截止频率 `1.5 Hz`、速度响应 `β=5.0 Hz/(m/s)`、导数截止频率 `1.0 Hz`。最小截止频率越低，静止时越平滑但滞后越大；β 越高，快速动作跟随越快但动态平滑较弱。导数截止频率通常保持默认。它按实际收到相机帧的主机单调时间计算，不假设固定FPS；新流、推理错误、倒退或重复时间戳、超过0.5秒间隔会重置。单张图等同于滤波首帧，不产生时序去噪。

在“SMPL 预览”选择“原始”“MLP 平滑”或“One Euro”。One Euro 和 MLP 可同时开启，各自处理原始结果；不是串联滤波。One Euro 不等待未来帧，不具有 MLP 的固定两帧中心窗口延迟，但仍有随动作频率和参数变化的相位滞后。

滤波对象是原始 CV 模型空间的 24 关节位置，每个坐标独立处理；不包含相机平移。导出的 root 关节由滤波后骨盆归零并用当前原始身体方向转回局部坐标。它不生成平滑 SMPL 旋转、不修改体型或姿态参数、不保证严格骨长；原 MHR 网格和原始字段保留。若要驱动机器人，还需基于目标机器人约束做姿态重定向。

`smpl_joints.csv` / `smpl_angles.csv` 新增 `one_euro` variant；`frames.jsonl` 新增 `smpl_keypoints_3d_one_euro`、`smpl_joints_one_euro_root`、滤波耗时、来源时间/帧及历史计数。参数保存在 `session.json` 的启动方案中。CSV 的 `lag_ms=0` 表示来源为当前输入，没有等待未来帧，**不表示滤波响应延迟为零**。原始参数、旋转和 MHR 数据仍单独保留。

## MHR 独立 One Euro 与原始对照（2026-11-04）

重开 Studio，在启动方案选择 **MHR 骨架＋One Euro**，点击“应用并预热”。无需勾选 SMPL 转换，也不需要 SMPL 模型文件。手动配置时，勾选 One Euro，并在“滤波目标”选择：

- **MHR 骨架**：分别滤波网络的 70 个三维关键点与 127 个 MHR 关节位置。
- **SMPL 骨架**：滤波转换后的 24 关节，需要启用 SMPL 转换。
- **MHR＋SMPL**：同时滤波两套位置，各自使用独立历史；需要 SMPL 转换。

原有未包含滤波目标的方案保持 SMPL-only 含义。MLP 仍只作用于 SMPL，和 One Euro 并行处理原始结果。参数、目标改变后需要重新应用预热。

结果区新增 **MHR 骨架 / 角度：原始 / One Euro** 切换，无需重新推理。它同步切换 3D 骨架、彩色图上的骨架以及肘膝角度；彩色图上的滤波骨架由滤波后三维关键点，配合当前原始相机平移和本帧有效内参重新投影。没有滤波结果时回到原始显示。连续显示可选择 **MHR 身体骨架预览**，只显示可旋转的身体线段（采用 MHR70 身体连线）；127 关节滤波结果保存在输出中，不把两套关节定义混为一谈。

这一阶段仅滤波位置。网格、姿态参数、相机平移和关节旋转保持原始，滤波骨架与原始网格可能略有错位。不保证严格骨长，也不生成滤波后的关节旋转。未接入网格平滑。

动作录制始终同时保存原始与可用滤波数据，不受当前预览选择影响：

| 文件 | 内容 |
| --- | --- |
| `frames.jsonl` / 单次结果 NPZ | 原始全部字段；新增 `mhr_keypoints_3d_one_euro` (70×3)、`mhr_joint_coords_one_euro` (127×3)、`mhr_keypoints_2d_one_euro`、投影有效掩码和滤波来源时间/帧/历史计数/耗时 |
| `angles.csv`、`keypoints.csv` | 原始角度和原始 70 个关键点，语义不变 |
| `mhr_filtered_angles.csv` | 根据滤波后三维关键点重新计算的角度 |
| `mhr_filtered_keypoints.csv` | 滤波后 70 个关键点及重新投影的像素坐标、有效标记 |
| `mhr_joints.csv` | 127 个原始与滤波关节位置，以 `variant=raw/one_euro` 区分 |

位置为模型尺度米，非标定世界坐标；来源时间是主机收到 RGB 的单调时间，不包括曝光及 USB 延迟。单张图没有历史，滤波值等于原始值；时序效果需连续推理观察。新流、非递增时间、超过 0.5 秒的间隔、推理错误会重置滤波历史。没有人体身份跟踪，换人应重新开始连续推理。One Euro 不等待未来帧，但有参数相关的跟随滞后，不能视作零延迟。

## MHR 参数实验室（2026-11-04）

桌面图标照常启动 Studio。窗口顶层新增 **SAM 3D 重建 / MHR 参数实验室** 两个标签页；第一个页面保留原来的图片、相机、启动方案、连续推理与动作导出功能。

实验室起点：

- **新建默认人体**：直接加载独立 MHR，不需要加载 SAM 图像网络。采用 204 个原生姿态/尺度参数、45 个体型系数、72 个表情系数全零的参考人体。本机约 1.73 m 高，这是模型默认尺度，不是实测身高。这里的零是 MHR 原生参数零，不是把图像网络的连续旋转编码清零。
- **导入最近一次预测**：复制第一个页面最近一次成功的单图结果或连续推理帧。导入后继续接收相机结果不会改变当前实验；再次点击导入才会更新实验起点。最近一次单图结果路径也保存在设置中，重开后仍可导入。
- **打开预测 / 实验 NPZ**：选择历史 `person_00.npz` 或实验室导出的 NPZ。修改与原始结果隔离，不覆盖预测文件。

左侧 **原生参数 321** 展示 `204 + 45 + 72` 个可编辑参数，包含当前值与初始值。选择一个参数，在右侧用滑杆或数值框修改。角度显示为度、内部保留弧度；尺度等使用原生单位。原生参数的 min/max 用作编辑范围，但不会裁剪导入值，也不意味着已做碰撞或全部解剖约束。某些固定参数的范围为零，不能通过原生编辑改变。

左侧 **预测原始值** 保留导入时的原始预测参数快照，包括连续姿态编码、身体姿态、手部参数、28 维尺度、45 维体型、72 维表情及相机平移等可用字段。它是只读对照，不随编辑变化。Fast 旧输出没有 `mhr_model_params` 时，实验室按原实现补齐 204 个原生参数，不加载骨干模型。导入时对比有/无姿态表面修正的重生成网格，选择与原预测更一致的设置；底部显示复现误差。

左侧 **骨架节点 127** 展示完整父子树。选中节点可查看局部/全局位置与旋转矩阵，以及关联的原生驱动参数。位置与矩阵统一使用 MHR 原生坐标（位置 cm），避免混用 SAM 的相机坐标位置和原生旋转。预览自动转换为 Studio 坐标（m）；红/绿/蓝轴对应节点局部 X/Y/Z。

勾选 **直接编辑所选节点**，可用三个旋转滑杆与三个平移滑杆覆盖该节点。旋转是相对绑定预旋转的 XYZ 欧拉参数；平移是绑定偏移外的局部平移参数，不是世界坐标位置。父节点变化仍会影响子节点。这种自由编辑可超出原生 204 参数能表达的范围，也可能改变骨长。取消勾选即移除此节点覆盖，恢复由当前原生参数驱动。

预览提供：

- **127 骨架**、选中节点坐标轴、正背侧视角、缩放和平移。
- **初始线框**：叠加未修改的起点网格。
- **位移热力图**：与起点逐顶点比较，蓝到红表示相对位移增大，颜色按本帧最大值归一化；底部另显示最大位移 cm。颜色不是绝对误差尺度。
- **姿态表面修正**：MHR 姿态相关表面修正网络开关，可对比弯曲处的外形变化。
- **恢复当前参数 / 全部恢复**：回到导入或默认起点，全部恢复也移除关节覆盖。

**导出参数 + 网格** 生成同名 `.npz`、`.json`、`.ply`。JSON 保存原生编辑参数、关节局部覆盖、基准值和坐标说明；NPZ 还保存原始预测快照、基准网格、当前网格、127 节点变换。PLY 顶点是 Studio 相机轴方向、米，不包含预测相机平移。存在关节覆盖时，单独拿 JSON/NPZ 中 204 个原生参数不能重现网格，必须同时应用 `overrides`。实验 NPZ 可重新打开继续编辑，并保留原始对照起点。

实验室使用独立进程，仅在创建/导入时加载 MHR；滑杆更新只运行参数到网格，不再次推理图片。快速拖动合并为最新请求，避免队列积压。可选择自动/CUDA 或 CPU，切换设备需重新创建/导入。**释放实验室模型** 只释放实验室资源；关闭窗口会同时清理实验室进程。SAM 与 MHR 可同时驻留，显存紧张时可在第一个页面释放 SAM 后继续实验。
